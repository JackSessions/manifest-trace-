## ManifestTrace v0.1.0: first release

Does an Android app's manifest leave something reachable that should not be. This generalises two of this author's own disclosed CVEs, CVE-2025-50861 (an exported activity reachable without authentication) and CVE-2025-50862 (allowBackup=true permitting data extraction over ADB backup), into a scanner that checks a batch of APKs for the same bug class.

```bash
pip install manifest-trace
manifest-trace app.apk
manifest-trace ./apks/
```

### What it checks

- exported_without_protection: an activity, service or receiver reachable by any other app, no permission
- exported_provider_wide_open: a content provider reachable by any other app, no read/write permission
- allow_backup_enabled: adb backup can pull this app's private data, no root needed
- debuggable_true: a debugger or adb shell run-as can attach to this app
- cleartext_traffic_allowed: this app may send unencrypted HTTP traffic

### How it was tested

A from-scratch, standard-library-only reader for Android's compiled binary XML manifest format (no androguard, no Android SDK) is proven against hand-built binary documents, byte for byte. The checks are proven against fake manifests, one that must fire per check and one clean one that must stay quiet. Separately, the whole pipeline is validated against two real, independently-built APKs: a well-known deliberately vulnerable training app, where it correctly found the documented exported-activity, exported-provider, allowBackup and debuggable issues without being tuned to that specific app, and a real modern open-source app as a clean baseline.

### Honest about the gaps

Manifest-level static analysis only. It does not decompile code, so it cannot confirm that an exported component is actually dangerous once reached, only that it is reachable. A finding is a lead for a human to confirm, not proof. No deep link validation, WebView checks or native library analysis yet. Tested against two real APKs so far; please report anything that behaves differently on a build you have.

### Using it responsibly

If this finds something real in an app you do not own, disclose it responsibly (ISO/IEC 29147) to the vendor before anything public, the same way this author's own CVEs were handled.
